04 · Pull requests get read

A review that has to show its working.

A webhook hands the diff to a model that returns a risk score and a list of flags, each one pinned to the exact lines it refers to. Findings that cannot be tied to the diff are dropped, and the card says so.

  • risk score, not a summary

    One number from zero to one hundred, so the triage can be a sort, not a read.

  • flags carry citations

    Each finding names a file and a line range. No line, no finding.

  • quiet when nothing is wrong

    The default outcome is no comment at all, not a padded review.

05 · Inventory

What it actually does

01

import-graph layout

Every file is a node

A force-directed layout over real import edges. Clusters are packages, hubs are the files everything depends on, and outliers are the ones worth reading.

02

complexity + churn + coupling

Health, not vibes

Each file is scored on cyclomatic complexity, churn over the last three months and its own coupling. The colour on the map is that number, not a gradient.

03

risk score + cited flags

Pull requests get read

A GitHub webhook hands the diff to a model and comes back with a risk score and a list of files with reasons attached. Quiet when nothing is wrong.

04

socket push + pinned comments

It stays live

Snapshots stream to open graphs over a WebSocket, and comment pins stay anchored to the coordinates you dropped them on. Two people can look at the same map.

05

snapshot history

Trend, not just state

Every analysis is kept. The history view plots health over time so a refactor that works shows up as a line going the right way.

06

FastAPI + SQLModel

Boring on purpose

FastAPI, SQLModel and Postgres behind it. SQLite by default, one Postgres URL on deploy. No vector database, no message queue you have to babysit.

01

one model call per review

Suggested open-source models refuse to count lines and cite files in long diffs, so the review runs a compressed view of the diff in one call with JSON output enforced. The model can only answer on evidence it actually saw.

02

health is three numbers

Complexity, churn and coupling collapse into one 0-100 score. The thresholds live in one file, the colour in one function, and nodes, tables and legends all read from the same source, so the map and the numbers never disagree.

03

migrations are the contract

Alembic owns the schema and a test diffs generated migrations against the models on every run. A schema change without its migration fails CI before it can drift.

04

the map is a force simulation

d3-force over real import edges, not a hand-drawn diagram. New files appear where imports put them, and the physics is the layout, so every repository maps honestly, including this one.

05

everything runs on free tiers

The backend is one Render free instance with a cold start of about fifty seconds, the database is Neon Free and the frontend ships from Vercel. Deploys run three or four times a day in both directions.
